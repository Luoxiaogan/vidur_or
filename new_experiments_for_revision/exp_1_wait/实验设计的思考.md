# LLM Serving Planning 理论分析

## 问题设置

考虑单一类型 (single type) 的 prompt 场景：
- **输入长度**：$l_0$ (in tokens)
- **输出长度**：$l_1$ (in tokens)
- **Threshold**：$n$（等待凑齐 $n$ 个请求后才允许做 admission，并且允许 admission $n$ 个，并且开始处理一个 batch）
- **到达率**：$\lambda$（外部请求到达率，requests/sec）
- **系统容量**：$C$（GPU memory 决定的最大并发 token 数）

---

## 1. Batch Token 数计算

在 decode 过程中，每一步的序列长度从 $l_0 + 1$ 增长到 $l_0 + l_1$。

对于 $n$ 个请求的 batch，总 token 数为：

$$M(n) = \sum_{i=1}^{l_1} (l_0 + i) \cdot n = n \cdot l_1 \cdot \left( l_0 + \frac{l_1 + 1}{2} \right)$$

定义**平均序列长度**：

$$\bar{l} = l_0 + \frac{l_1 + 1}{2}$$

则：

$$M(n) = n \cdot l_1 \cdot \bar{l}$$

---

## 2. 延迟模型

假设处理一个 batch 的时间为：

$$\Delta T = d_0 + d_1 \cdot M(n) = d_0 + d_1 \cdot n \cdot l_1 \cdot \bar{l}$$

其中：
- $d_0$：固定开销（与 batch 大小无关）
- $d_1$：每 token 的处理时间

> **注意**：这是简化的线性模型。实际中 Attention 复杂度为 $O(n \cdot l^2)$，且存在 memory bandwidth 瓶颈。建议从实验数据拟合 $d_0, d_1$。

---

## 3. 稳态分析

### 稳态条件

在稳态下，**吞吐量 = 到达率**：

$$\text{avg-throughput} = \frac{n}{\Delta T} = \lambda$$

由此得到：

$$(d_0 + d_1 \cdot n \cdot l_1 \cdot \bar{l}) \cdot \lambda = n$$

### 最优 Threshold

解上述方程，得到最优 threshold：

$$\boxed{n^* = \frac{d_0 \lambda}{1 - d_1 l_1 \bar{l} \lambda}}$$

> **注**：$n^*$ 正比于外部到达率 $\lambda$，且要求 $d_1 l_1 \bar{l} \lambda < 1$（系统稳定条件）。

### 对应的 Batch Token 数

$$\boxed{M^* = \frac{d_0 l_1 \bar{l} \lambda}{1 - d_1 l_1 \bar{l} \lambda}}$$

当 $\lambda$ 增大时，$M^*$ 也随之增大，直到接近系统容量上限 $C$。

### GPU 处理延迟

在 GPU 上的处理延迟为（不含队列等待时间）：

$$\boxed{\Delta T = d_0 + d_1 l_1 \bar{l} \cdot n^* = \frac{d_0}{1 - d_1 l_1 \bar{l} \lambda}}$$

### 端到端延迟（含等待时间）

实际的 E2E latency 还包括**等待时间**（等待凑齐 $n$ 个请求）：

$$\boxed{\text{E2E latency} = \underbrace{\frac{n}{2\lambda}}_{\text{等待时间}} + \underbrace{\Delta T}_{\text{处理时间}}}$$

等待时间 $\frac{n}{2\lambda}$ 是期望等待半个 batch 的时间。

---

## 4. 待用实验证明的结论

**命题**：固定容量 $C$、type、$\lambda$，最优的 threshold 是 $n^*(\lambda)$。

对于其他 $n$，batch token 数为(这个是当然的)：

$$M(n) = n \cdot l_1 \cdot \bar{l}$$

### Throughput vs Threshold 关系图

```
avg-throughput
     ↑
     │    ╭──╮
     │   ╱    ╲
     │  ╱      ╲
     │ ╱        ╲→
     │╱
     └─────────────→ n
           n*
```

在 $n = n^*$ 处，avg-throughput 达到最大值 $\lambda$；偏离 $n^*$ 时，throughput 下降。

---

## 5. 总结

| 指标 | 稳态表达式 |
|------|-----------|
| 最优 Threshold | $n^* = \dfrac{d_0 \lambda}{1 - d_1 l_1 \bar{l} \lambda}$ |
| Batch Token 数 | $M^* = \dfrac{d_0 l_1 \bar{l} \lambda}{1 - d_1 l_1 \bar{l} \lambda}$ |
| GPU 处理延迟 | $\Delta T = \dfrac{d_0}{1 - d_1 l_1 \bar{l} \lambda}$ |
| E2E 延迟 | $\dfrac{n^*}{2\lambda} + \Delta T$ |
| 平均吞吐量 | $\dfrac{n^*}{\Delta T} = \lambda$ |

**关键洞察**：
1. $n^*$ 和 $M^*$ 都随 $\lambda$ 增大而增大
2. 系统稳定要求 $d_1 l_1 \bar{l} \lambda < 1$
3. 存在最优 threshold 使得系统达到目标吞吐量
4. E2E 延迟包含等待时间，这会影响 latency-throughput tradeoff

---

## 6. 实验验证方向

基于上述理论分析，实验应验证：

1. **验证 $n^*(\lambda)$ 关系**：固定 $\lambda$，变化 $n$，找到使 throughput 最大化的 $n^*$
2. **验证稳定性边界**：逐渐增大 $\lambda$，找到系统从 stable 变为 unstable 的临界点
3. **验证 latency-throughput tradeoff**：画出 Pareto 曲线（对应审稿人要求的 "Mean Latency vs Arrival Rate"）
4. **拟合模型参数**：从实验数据估计 $d_0, d_1$，验证线性假设的适用范围
