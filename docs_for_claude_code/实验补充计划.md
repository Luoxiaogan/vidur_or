## 一、必须补充的实验

### 1.1 Stable Regime 实验 (Reviewer 3 核心意见)

**问题**：当前所有实验都在 unstable regime 下进行（从 latency 图的持续增长可以看出）。测试 unstable regime 对 throughput 差异有意义，但对 latency 没有意义。

**需要补充**：
- **Mean Latency vs Arrival Rate 曲线**
  - 横轴：arrival rate (从低到高，跨越 stable 到 unstable 边界)
  - 纵轴：稳态平均 latency
  - 对比：WAIT (booking limit) / Nested WAIT / vLLM / Sarathi
  - 目的：展示不同算法的 **stability region 差异**

- **Throughput vs Arrival Rate 曲线**
  - 类似设置，展示各算法能维持的最大稳定 throughput

### 1.2 Near-Boundary 实验 (Nested WAIT 专项)

**需要补充**：
- 在接近 capacity boundary (C ≈ M*) 的 regime 下
- 画 **Latency-Time 曲线**，展示系统是否稳定
- 对比 Nested WAIT vs baseline 在边界附近的表现

### 1.3 Wait vs No-Wait Tradeoff 实验 (Reviewer 2 建议)

**问题**：如果算法不等待（仍使用 threshold n_j 但不等待积累到 n_j 个 prompts），会怎样？

**需要补充**：
- **对比实验**：WAIT (等待) vs Threshold-without-Waiting (不等待)
- **不同 load 下的表现**：
  - Light load：WAIT 可能有额外 latency penalty
  - Near capacity：WAIT 应该显著优于不等待的版本
- 目的：展示 waiting 机制的价值，回应审稿人关于 alternative algorithms 的问题

## 七、实验设计要点

### 7.1 核心对比维度

所有实验应包含以下对比：
1. **WAIT (Booking Limit)** vs **Nested WAIT (Nested Booking Limit)**
2. **我们的算法** vs **vLLM** vs **Sarathi**
3. **不同 load 水平**：underloaded / near-capacity / overloaded

### 7.2 关键指标

- **Throughput**：completions per second
- **Latency**：end-to-end latency (mean, p50, p99)
- **TTFT**：Time to First Token
- **Memory usage**：KV cache 占用

### 7.3 实验目标

通过实验展示：
1. **Eviction prevention**：我们的算法避免 cascading failure
2. **Stability region**：我们的算法有更大的 stable region
3. **Memory exploitation**：在 near-capacity 下充分利用 memory 提高 throughput
4. **On-the-fly classification**：Nested WAIT 让短请求不被长请求拖累
