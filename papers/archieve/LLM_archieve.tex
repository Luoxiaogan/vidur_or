\section{Model}
We consider a framework of LLM inference. We have discrete time horizon $[T]$. For each time $t\in[T],$ there are $N^t$ tasks arriving to the system, denoted by $(X_1^{t},Q_1^{t}),\dots(X_{N^t}^{t},Q_{N^t}^{t})$, where $X_i^{t},Q_i^{t}$ stand for contexts and queries, respectively. Before being sent to pre-processing, each context $X_i^{t}$ needs to be splitted into multiple chunks, say $\phi(X_i^t) = [Z_{i1}^t,\dots,Z_{im}^t]$, where $m$ denotes number of chunks. According to $Q_i^t,$ each task is marked as nested difficulty levels $l_i^t\in\{1,\dots,n\}.$ The time cost of pre-processing task $(X_1^{t},Q_1^{t})$ is given by $D_{l_i^t}(\phi(X_i^t))=\sum_{j=1}^mD_{l_i^t}(Z_{ij}^t)$. After pre-processing $(X_1^{t},Q_1^{t}),$ is has probability $P_{l_i^t}(\phi(X_i^t))=P_{l_i^t}(Z_i^t)$ to be converted to task of level $l_i^t+1$ and $1-P_{l_i^t}(Z_i^t)$ to be sent to the next stage. Each At the same time, there are total number of $N$ channels that can pre-process simultaneously. The objective is to minimize the total waiting costs by simultaneously optimize the splitting map as well as the channel allocation.

\section{Model B}
We consider a framework of LLM inference. We have discrete time horizon $[T]$. For each time $t\in[T],$ there are $N^t$ tasks arriving to the system, denoted by $(X_1^{t},Q_1^{t}),\dots(X_{N^t}^{t},Q_{N^t}^{t})$, where $X_i^{t},Q_i^{t}$ stand for contexts and queries, respectively. Here, the queries and contexts are not explicitly separated since the query is extracted later during the task of performing query extraction on the chunks. Before being sent to pre-processing, each prompt $(X_i^{t}, Q_i^t)$ needs to be splitted into multiple chunks, say $\phi(X_i^{t}, Q_i^t) = [Z_{i1}^t,\dots,Z_{im}^t]$, where $m$ denotes number of chunks. 

Since we have not yet extracted the queries, we first need to perform basic pre-processing tasks on each chunk. Specifically, this involves applying basic formatting standards to each chunk, followed by using an NLP model to extract the queries. For simplicity, these tasks are marked as task$_1$, task$_2$. After extracting the query, each kind of task is marked as $\{3,\dots,n\}$ sequentially.

For each kind of task$_k$, the computational resources constraint and the GPU memory constraint is formulated as the number of channels $N_k$ that can pre-process simultaneously and they should wait for schedule and the memory limit $M_k$. So for the chunks in process, their total memory should not exceed $M_k$. Since this is a constraint on a specific task, it can often be simplified to a single constraint. For example, when calling an API, the actual constraint is typically the channel constraint caused by network bandwidth. Similarly, when using a local model for processing, the actual constraint is usually the memory constraint.

After the task$_k$ on chunk $Z_{il}^t$, is has probability $P_k(Z_{il}^t)$ to be sent to task$_{k+1}$ and $1-P_k(Z_{il}^t)$ to reprocess.

The time cost of task$_k$ on chunk $Z_{il}^t$, is given by $D_k(Z_{il}^t)=\alpha_k+\beta_k|Z_{il}^t|^{\gamma_k}$ or $D_k(Z_{il}^t)=\max\{\alpha_k,\beta_k|Z_{il}^t|^{\gamma_k}\}$, where $|Z_{il}^t|$ denote the number of tokens in $Z_{il}^t$ and $\gamma_k$ usually equals to $1$. For special tasks like query-guided chunk completion, the processing time can be influenced by the query.

\begin{align*}
D_k(Z_{il}^t)&=\alpha_k+\beta_k|Z_{il}^t|^{\gamma_k}\\
    D_k(Z_{il}^t)&=\max\{\alpha_k,\beta_k|Z_{il}^t|^{\gamma_k}\}
\end{align*}

The total time cost of each chunk $Z_{il}^{t}$, denoted by $D(Z_{il}^t)$, is not $\sum_{k=1}^n D_k(Z_{il}^t)$, since, for certain tasks, their computational and memory resources may be utilized by other chunks from the same prompt or from other prompts. 

The total time cost of prompt $(X_i^t, Q_i^t)$, denoted by $D(X_i^t, Q_i^t)$ is given by $\max_{l}\{D(Z_{il}^t)\}$.

The objective is to minimize the total waiting costs by simultaneously optimize the splitting map as well as the channel allocation.
