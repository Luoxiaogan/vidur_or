\section{Model}
We consider the scheduling of inference in LLM. In this stage, the each prompt is already embedded into a series of tokens and wait to get inference. To begin with, there are two stages in the inference: prefill and decode. 

When the prompts arrive, they will be passed through the model to calculate the KV cache. After the computation, the KV cache can be stored either in the GPU when the memory capacity is available or transferred to the CPU. Recent research shows that the prefilling stage can be splitted into multiple iterations: one can split the tokens sequence of one prompt into several chunks and calculate each chunk's KV cache in one iteration. This can reduce the bubble (i.e. the waste of memory of GPU) during each GPU computation iteration. Therefore, a tradeoff is how to split the prefilling chunks to better exploit the computation resources.

After being prefilled, each prompt's token sequence needs to be sent to the model for decoding. In each iteration of GPU, the model will utilize the previous KV cache of each prompt to generate a new token and compute the new KV cache by adding the new token. The new KV cache will be stored on GPU memory. The decoding stage for each prompt will end if the token with signal of ending is generated. 

For each iteration of computation on GPU, we will form a \textbf{batch} of tokens that consist of the following parts: the \textbf{prefilling chunks} of some prompts within prefilling stage and the \textbf{whole token sequence} of each prompt within decoding stage. We cannot do operations on GPU until one iteration completes, which is the timing of the latest completion of computation in the batch. For each iteration, we need to do \textbf{batching} scheduling, which decides how to split the prefilling chunks and assign the prompts / chunks to each iteration's batch. Due to the limited GPU memory capacity, we need to decide how to make chunking as well as batching scheduling.
% The main tradeoff is: the memory capacity of the GPU is limited. For $l$ tokens, there are $l$ units of memory needed to store the KV cache. 

We now present the mathematical notations we will use to formulate the problem. We assume there is one GPU, which has memory capacity $C$ for computation left after loading model parameters. We assume that the CPU does not have memory limit. We assume each token requires $1$ unit of capacity to store its KV cache and other parameters. We assume that $l$ tokens require $l$ units of storage capacity. Loading one token's KV cache from CPU takes time $d_s.$ \arc{Whether considering CPU is problem, maybe after we develop theory without this part} For a token sequence of length $l$, it takes time $d_f\cdot l$ to make one forward propgation iteration of prefilling and $d_c$ for iteration of decoding. For a batch consisting of prefilling chunks of length $k_1,\dots,k_{n_1}$ and decoding prompts of length $l_1,\dots,l_{n_2},$ it takes time of $\max\{d_s\cdot \max_{i\in[n_1]}\{k_i\cdot u_i\}+ d_f\max_{i\in[n_1]}\{k_i\}, d_c\sum_{i=1}^{n_2}l_i\}$, where $u_i\in\{0,1\},i\in[n_1]$ denote the indicators of being at CPU. We assume that $d_f \le d_c$ as prefilling typically takes less time. The \textbf{time to first token (TTFT)} of each prompt measures how quickly users begin to see the first token generated in decoding stage. The \textbf{Time per output token (TPOT)} measures the mean time to generate each output token in decoding stage. \textbf{Latency} is the time of the completing the last token's decoding. \textbf{Throughput} is the number of token generated per unit time across all requests by the inference server. 

Our objective is 
\begin{equation}
    \label{prob:maximize}
    \begin{aligned}
        \max_{\text{prefilling chunking, batch scheduling}} \qquad & \textbf{Throughput}\\ 
        \st \qquad & \textbf{TTFT} \le t_f,\\
        & \textbf{Latency} \le t_l,\\ 
        & \textbf{Occupied memory} \le C.
    \end{aligned}
\end{equation}

\subsection{Benchmark}
We consider the fluid equilibrium, where the arrive rates equal to the optimal output rates. Specifically, We assume there are $m$ types of of prompts, with type $j$ of length $l_j$ after prefilling and $l_j+l_j'$ after decoding. Therefore, each prompt of type $j$ will have to be processed with at least $1+l_j'$ iterations with at least $1$ prefilling iteration. We say type $j$ is at stage $0<k<l_j+1$ if it is algready decoded $k-1$ and at stage $0$ if it has not completed the prefilling.  We assume the arrival rate of type $j$ is $\lambda_j$ at each time $t$. 

Now we consider the fluid benchmark, which has exact $\lambda_j$ arrivals at each time $t$ and the output equals to the input. Specifically, we assume that at time $t$, there are $n_{jk}^t$ of type $j$ tokens in the iteration. For one prompt of type $j$, it takes exactly $l_j'$ iterations of decoding for output. We start with the single type scenario. At equilibrium, the output should equal to the input in certain period. We have $n_j\equiv n_j^t = \sum_{k=1}^{l_j'}n_{jk}^t$ being constant over time. It follows that 
\begin{equation}
    \sum_{k=1}^{l_j'}(d_1+n_j(l_j+k)d_c) \lambda_j = n_j,
\end{equation}
where the left side represents the time to process the $n_j$ prompts multiplied by arrival rate $\lambda_j$. It follows that 
\begin{equation}
    n_j = \frac{\lambda l_j'd_1}{1-\lambda d_cl_j(2l_j+l_j'+1)/2}
\end{equation}
with throughput 
\begin{equation}
    \throughput = n_j(l_j+l_j') / (n_j/\lambda_j) = (l_j+l_j')\lambda_j.
\end{equation}
We have the following proposition.
\begin{proposition}
    \label{prop:throughput_fluid_single}
    For single type $j$, the equilibrium throughput is 
    \begin{align*}
        \throughput = (l_j+l_j')\lambda_j.
    \end{align*}
    Moreover, over all equilibrium fluid policies that reach the throughput above, the load-balanced policy reaches the minimal \textbf{TTFT} and \text{Latency}, i.e. we have optimal $n_j^t = j/k.$
\end{proposition}

Now this can be extended to the multiple type scenario. Specifically, we have 
\begin{equation}
    \label{eq:fluid_equations}
   \prn{d_1+ \sum_{j=1}^m \frac{n_j}{l_j'}\frac{l_j'(2l_j+l_j'+1)}{2}}\lambda_i = n_i,\quad i\in[m].
\end{equation}
It follows that
\begin{equation*}
    \frac{n_1}{\lambda_1} = \frac{n_2}{\lambda_2} = \dots = \frac{n_m}{\lambda_m}.
\end{equation*}
The minimal memmory capacity we need to get the equilibrium is:
\begin{equation}
   \underset{(i)}{ \underbrace{\sum_{j=1}^m \frac{n_j(2l_j+l_j'+1)}{2}}}  + \underset{(ii)}{\underbrace{\sum_{j=1}^m\frac{n_jl_j}{l_j'} }},
\end{equation}
where $(i)$ denotes the decoding memory occupancy and $(ii)$ denotes the prefilling memory occupancy.

The throughput is given by 
\begin{equation}
    \throughput = \prn{d_1+ \sum_{j=1}^m \frac{n_j}{l_j'}\frac{l_j'(2l_j+l_j'+1)}{2}}^{-1}\prn{\sum_{j=1}^m(n_j+l_j)}
\end{equation}

\subsection{Stochastic arrivals with known type}
Now assume at each time, the arrivals of type $j$ follows Poisson distribution $P(\lambda_j)$. Our target is to build a load-balance algorithm. Specifically, we consider a booking-limit policy, which waits to collect exact the number of prompts of each type and each stage solved in \eqref{eq:fluid_equations}. At time $t$, upon observe the actual arrivals $\Lambda^t$ and current prompt inventory level $n_{jk}^t,j\in[m],0\le k\le l_j'.$ We will start new iteration if and only if we have $n_{jk}^t \ge n_{jk}^\star$ for all $j,k$, where $n_{jk}^\star$ are solutions to \eqref{eq:fluid_equations}. When the above condition is satisfied, we will wrap up exact the amount of $n_{jk}^\star$ of each type at each stage to a batch and run an iteration. This can avoid repeatedly load / move the KV cache from GPU to lower level of memory.

To prove the theoretic guarantee, we consider two heavy-traffic scenario: (i) conventional heavy-traffic scaling; (ii) many-server heavy-traffic scaling. The first is obtained by scaling up both the arrival rate and the processing speed while the later scales up the memory and the arrival rate.

\subsubsection{Many-Server Heavy-Traffic}
In this case, we consider the model with $\lambda_j^{(\zeta)} = \zeta\lambda$ and $c^{(\zeta)} = \zeta c,$ while the time interval is compressed by $1/\zeta.$ Therefore, we still consider the average throughput in discrete time horizon $1,2,\dots,T,$ while $d_c,d_1$ keep invariant. Denote $\throughput^{\zeta,\pi}$ as the average throughput in the system scaled by $\zeta$:
\begin{equation*}
    \throughput^{\zeta,\pi} = \frac{1}{T}\sum_{j=1}^m N_j^{(\zeta,\pi,T)}
\end{equation*}
\begin{theorem}
    \label{thm:many_server}
    \begin{equation*}
        \liminf_{\zeta\to+\infty} \throughput^{\zeta,\pi} \ge \throughput^\star.
    \end{equation*}
\end{theorem}
\subsubsection{Many-Server Heavy-Traffic}
In this case, we consider the model with $\lambda_j^{(\zeta)} = \zeta\lambda$ and $c^{(\zeta)} = \zeta c,$ while the time interval is compressed by $1/\zeta.$ Therefore, we still consider the average throughput in discrete time horizon $1,2,\dots,T,$ while $d_c,d_1$ keep invariant. Denote $\throughput^{\zeta,\pi}$ as the average throughput in the system scaled by $\zeta$:
\begin{equation*}
    \throughput^{\zeta,\pi} = \frac{1}{T}\sum_{j=1}^m N_j^{(\zeta,\pi,T)}
\end{equation*}
\begin{theorem}
    \label{thm:many_server}
    \begin{equation*}
        \liminf_{\zeta\to+\infty}\zeta^{-1} \ex{}{\throughput^{\zeta,\pi}} \ge (1-T^{-1})\throughput^\star.
    \end{equation*}
\end{theorem}
\subsubsection{Conventional Heavy-Traffic}
In this case, we consider the model with arrival rates and processing speed scaled up by $\zeta$, which can be represented by scaling the discrete time horizon as $T\to \zeta T.$ Therefore, we can consider the average throughput in discrete time horizon $1,2,\dots,\zeta T,$ while $\lambda,c,d_c,d_1$ keep invariant. Denote $\throughput^{\zeta,\pi}$ as the average throughput in the system scaled by $\zeta$:
\begin{equation*}
    \throughput^{\zeta,\pi} = \frac{1}{\zeta T}\sum_{j=1}^m N_j^{(\pi,\zeta T)}
\end{equation*}
\begin{theorem}
    \label{thm:many_server}
    \begin{equation*}
        \liminf_{\zeta\to+\infty} \ex{}{\throughput^{\zeta,\pi}} \ge \throughput^\star.
    \end{equation*}
\end{theorem}

First, consider the scenario with only one type. For the booking limit policy, it can be inferred from the recursion that the waiting time is necessarily spent on awaiting the accumulation of sufficient prompts for prefill.

\begin{lemma}\label{throughput gap}
The number of incoming prompts $X_t$ at each time step $n$ follows a Poisson distribution with parameter $\lambda$. The service processes up $\lambda$ prompts at each time step when there are at least $\lambda$ prompts available. Let $W_t$ represent the number of prompts in the queue at time $t$, starting with $W_0=0$. The state transition rule is given by
$$W_{t+1}=W_t+X_t-\lambda\cdot \mathbf{1}\{W_t+X_t\geq \lambda\}$$

Define the total number of stuck time steps as $T_{\text{stuck}}$, which is also the total number of time steps of $W_t+X_t<\lambda$, and the following relationship holds
$$\mathbb{E}[W_T]= \lambda\cdot\mathbb{E}[T_{\text{stuck}}].$$
\end{lemma}
The proof is easy, just taking the expectation on both sides of the state transition equation
$$\ex{}{W_{t+1}}=\ex{}{W_t}+\lambda - \lambda \mathbb{P}(W_t+X_t\geq \lambda)$$
Summing from $t=0$ to $T-1$, and noting that $W_0=0$, we get the lemma
$$\ex{}{W_T}=\lambda T - \lambda \ex{}{T-T_{\text{stuck}}}=\lambda\cdot \ex{}{T_{\text{stuck}}}$$

\begin{lemma}\label{coupled process}
Define a new process $\{\tilde{W}_t\}$ as a coupled version of $\{W_t\}$ as follows:
$$
\tilde{W}_0 = 2\lambda, \quad \tilde{W}_{t+1} = \max\{ 2\lambda, \tilde{W}_t + X_t - \lambda \}.
$$
Then, we have $\tilde{W}_t \geq W_t + \lambda, \;\forall t\in \mathbb{N}$.
\end{lemma}
We prove this by induction. First, for $t = 0$, we have $\tilde{W}_0=2\lambda\geq \lambda=W_0+\lambda$. Next, assume that $\tilde{W}_t \geq W_t + \lambda$ holds for some $t \geq 0$. We now prove that $\tilde{W}_{t+1} \geq W_{t+1} + \lambda$. Consider the following two cases:

1. If $W_t + X_t \geq \lambda$, then $W_{t+1} = W_t + X_t - \lambda$. In this case,
$$\tilde{W}_{t+1}=\max\{ 2\lambda, \tilde{W}_t + X_t - \lambda \}\geq \tilde{W}_t + X_t - \lambda\geq( W_t+\lambda )+ X_t - \lambda=W_{t+1}+\lambda.$$

2. If $W_t + X_t < \lambda$, then $W_{t+1} = W_t + X_t$. In this case,
$$\tilde{W}_{t+1}=\max\{ 2\lambda, \tilde{W}_t + X_t - \lambda \}\geq 2\lambda = \lambda+\lambda>W_{t+1}+\lambda.$$
Hence, $\tilde{W}_{t+1} \geq W_{t+1} + \lambda$. By the principle of induction, we have $\tilde{W}_t \geq W_t + \lambda$ for all $t \in \mathbb{N}$.

By Proposition 6.3 in \cite{asmussen2003applied}, we have that 
\begin{lemma}
    $$\tilde{W}_T=2\lambda+\max(S_T, S_T-S_1,\cdots,S_T-S_{T-1},0),\; S_k=\sum_{r=1}^k (X_r-\lambda) $$
\end{lemma}
Let $\xi_k = X_k-\lambda$, and notice that 
$$\max(S_T, S_T-S_1,\cdots,S_T-S_{T-1},0)=\max_{1\leq k\leq T}(\sum_{r=k}^{T}\xi_r)^+\overset{d}{=}\max_{1\leq s\leq T}(\sum_{r=1}^{s}\eta_r)^+, \; \eta_r\overset{d}{=}X_1-\lambda$$
So we have that $\tilde{W}_T \overset{d}{=}2\lambda+\max_{1\leq s\leq T}(\sum_{r=1}^{s}\eta_r)^+ $. 

Since $\tilde{W}_T \geq \lambda+W_T$, we have $\mathbb{E}[W_T]\leq \mathbb{E}[\tilde{W}_T]-\lambda = \mathbb{E}[\max_{1\leq s\leq T}(\sum_{r=1}^{s}\eta_r)^+]+\lambda$. Let $Y_T = \max_{1\leq s\leq T}(\sum_{r=1}^{s}\eta_r)^+$, consider the expectation $\ex{}{Y_T}$.
By the lemma2 in \cite{strait1974maximum}, we get that
\begin{lemma}
    $$\ex{}{Y_T}=\ex{}{\max_{1\leq s\leq T}(\sum_{r=1}^s\eta_r)^+}=\ex{}{\max_{1\leq k\leq T}S_k^+}=\sum_{k=1}^T \frac{1}{k}\ex{}{S_k^+}$$
\end{lemma}
Then we consider the $\mathbb{E}[S_k^+]$, and just use the Cauchy's inequality
\begin{align*}
&\mathbb{E}[S_k^+]=\mathbb{E}[\max\{S_k,0\}]\leq \ex{}{|S_k|}\leq \sqrt{\ex{}{S_k^2}}=\sigma\sqrt{k}=\sqrt{\lambda k}\\
\Rightarrow& \ex{}{Y_T}\leq \sqrt{\lambda}\sum_{k=1}^T \frac{1}{\sqrt{k}} \sim \sqrt{\lambda T}
\end{align*}
So we have that 
\begin{lemma}\label{lemma::throughput gap}
    $$\mathbb{E}[W_T]-\lambda\leq \mathbb{E}[Y_T]\leq  \sqrt{\lambda} \sum_{k=1}^T \frac{1}{\sqrt{k}} \sim\sqrt{\lambda T},\; T\to \infty$$
\end{lemma}
Then consider the average throughput. In the deterministic scenario, the average throughput $\throughput^* = \lambda$. Thus, in the stochastic case, the expected gap between the average throughput $\throughput$ and $\throughput^*$ is given by $\frac{1}{T}\mathbb{E}[W_T]$.\\
In \textbf{Many-Server Heavy-Traffic} case, 
\begin{align*}
    \frac{1}{T^{\zeta}}\ex{}{W_T^{\zeta}}=\frac{\lambda^{\zeta}+\sqrt{\lambda^{\zeta}T^{\zeta}}}{T^{\zeta}}=\frac{\zeta\lambda+\sqrt{\zeta\lambda \zeta T }}{\zeta T}=\frac{\lambda+\sqrt{\lambda T}}{T}\to 0,\; T\to \infty
\end{align*}
In \textbf{Conventional Heavy-Traffic} case, 
\begin{align*}
    \frac{1}{T^{\zeta}}\ex{}{W_T^{\zeta}}=\frac{\lambda^{\zeta}+\sqrt{\lambda^{\zeta}T^{\zeta}}}{T^{\zeta}}=\frac{\lambda+\sqrt{\lambda \zeta T }}{\zeta T}\to 0,\; \zeta\to \infty 
\end{align*}

Next, we consider the scenario with multiple types of prompts. In this scenario, our booking limit policy is expressed as follows: there are $m$ independent $W_t^{(i)}$. At time $t$, processing occurs only if $W_t^{(i)} \geq \lambda_i$ holds for all $i=1,\cdots,m$. In this case, under the deterministic scenario where $\lambda_i$ prompts of type $i$ arrive at each time step, the average throughput, given by $\lambda_1 + \dots + \lambda_m$, represents the optimal average throughput.

In the stochastic case, the gap between the throughput from time $0$ to $T$ and the optimal throughput $T(\lambda_1 + \dots + \lambda_m)$ can be bounded above using $W_T^{(i)}$ from the single-type scenario.

The worst-case scenario occurs when at least $\lambda_i$ prompts are queued for the other $m-1$ types, but one remaining type fails to satisfy the condition to start processing. Therefore, for each type, the expected upper bound of the stuck time is $\mathbb{E}\left[\sum_{j=1}^m T^{(j)}_{\text{stuck}}\right]$. Consequently, using the Lemma \ref{throughput gap}, we have that the expected upper bound of the final gap is given by
$$
\left(\sum_{i=1}^m \lambda_i\right)\cdot \mathbb{E}\left[\sum_{j=1}^m T^{(j)}_{\text{stuck}}\right]=\left(\sum_{i=1}^m \lambda_i\right)\cdot \mathbb{E}\left[\sum_{j=1}^m \frac{1}{\lambda_j}W_T^{(j)}\right]=\sum_{i=1}^m\sum_{j=1}^m\frac{\lambda_i}{\lambda_j}\mathbb{E}[W_T^{(j)}]
$$
So the expected upper bound of the gap of average throughput is that 
$$\frac{1}{T}\sum_{i=1}^m\sum_{j=1}^m\frac{\lambda_i}{\lambda_j}\mathbb{E}[W_T^{(j)}]\leq \frac{1}{T}\sum_{i=1}^m\sum_{j=1}^m\frac{\lambda_i}{\lambda_j}\left( \lambda_j+\sqrt{\lambda_jT} \right)=\frac{m}{T}\sum_{i=1}^m\lambda_i+\frac{1}{\sqrt{T}}\sum_{i=1}^m\sum_{j=1}^m\sqrt{\frac{\lambda_i}{\lambda_j}}$$
In \textbf{Many-Server Heavy-Traffic} case, 
\begin{align*}
   \frac{m}{T^{\zeta}}\sum_{i=1}^m\lambda_i^{\zeta}+\frac{1}{\sqrt{T^{\zeta}}}\sum_{i=1}^m\sum_{j=1}^m\sqrt{\frac{\lambda_i^{\zeta}}{\lambda_j^{\zeta}}}= \frac{m}{\zeta T}\sum_{i=1}^m\zeta\lambda_i+\frac{1}{\sqrt{\zeta T}}\sum_{i=1}^m\sum_{j=1}^m\sqrt{\frac{\lambda_i}{\lambda_j}}\underbrace{\to \frac{m}{T}\sum_{i=1}^m\lambda_i}_{\zeta\to \infty}\to 0,\; T\to \infty 
\end{align*}
In \textbf{Conventional Heavy-Traffic} case, 
\begin{align*}
 \frac{m}{T^{\zeta}}\sum_{i=1}^m\lambda_i^{\zeta}+\frac{1}{\sqrt{T^{\zeta}}}\sum_{i=1}^m\sum_{j=1}^m\sqrt{\frac{\lambda_i^{\zeta}}{\lambda_j^{\zeta}}}= \frac{m}{\zeta T}\sum_{i=1}^m\lambda_i+\frac{1}{\sqrt{\zeta T}}\sum_{i=1}^m\sum_{j=1}^m\sqrt{\frac{\lambda_i}{\lambda_j}}\to 0,\; \zeta\to \infty
\end{align*}


\subsection{Stochastic arrivals with unknown type}

Assume there are $ m $ types of incoming prompts, each following a Poisson distribution with parameter $\lambda_i$, and suppose their input lengths are all $ l $, while the required number of decoding steps is $ l^{\prime}_1 < l^{\prime}_2 < \cdots < l^{\prime}_{m}$. Therefore, for a prompt of type $i$, one prefill operation and $l^{\prime}_i$ decode operations are required.

\subsubsection{Many-Server Heavy-Traffic}
Consider the nested booking limit policy. We divide the entire process into $m$ segments. In the first segment, the total arrival rate is $\lambda_1 + \cdots + \lambda_m$, and $1 + l^{\prime}_1$ iterations need to be processed. Subsequently, the process enters the second segment, $l^{\prime}_2-l^{\prime}_1$ iterations are required. This pattern continues analogously for the remaining segments. When the number of prompts required by the booking-limit policy for the $i$-th segment is insufficient, the work of the $i$-th segment and all subsequent segments will be paused. The process will resume only when the required number of prompts becomes sufficient. Note that the preceding segments remain unaffected.

Consider a simple example. There are two types of prompts, arriving at rates $\lambda_1$ and $\lambda_2$, respectively. Both have the same initial length $l$, but require different numbers of decoding steps, with $l^{\prime}_1 < l^{\prime}_2$. In segment 1, the arrival rate is $\lambda_1 + \lambda_2$, and $1 + l^{\prime}_1$ iterations need to be executed. In segment 2, $1 + l^{\prime}_2$ iterations are required. 

We first consider the fluid benchmark, which has exact $\lambda_i$ arrivals at each time $t$ and the
output is equal to the input. Set the number of tasks in each stage is constant and denoted as $n_1$ and $n_2$ for type 1 and type 2, respectively. The total memory usage $M$ is given by:
$$M = n_1 \sum_{i=1}^{l_1'} (l + i) + n_2 \sum_{i=l_1^{\prime}+1}^{l_2'} (l + i) = n_1 \left( l \cdot l_1' + \frac{l_1' (l_1' + 1)}{2} \right) + n_2 \left( l\cdot( l_2'-l_1^{\prime}) + \frac{(l_2'-l_1^{\prime} ) (l_1'+l_2' + 1)}{2} \right).$$
The equilibrium conditions are:
$$(d_0 + d_1 M) \lambda_1 = n_1,\;\textcolor{red}{\text{seems should be }n_1-n_2 \text{ instead?}} \; (d_0 + d_1 M) \lambda_2 = n_2.$$
Solving the system of equations yields:
\begin{align*}

\end{align*}
Therefore, we have derived the memory requirements for two scenarios:

    \item $M_1$: The memory required when processing only Segment 1.
\end{itemize}
